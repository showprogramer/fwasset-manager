# 更新程序对话框与范围下拉

状态：已完成

## 1. 目标

把「换版本」对话框改成「更新程序」：用户把表单填成目标样子，软件按改了哪几项派生操作，不再先选「换版本 / 换到另一模块 / 改到定制 / 改回通用 / 换方案」。新建程序的「通用/定制」同步改成同一个范围下拉。

## 2. 已定决定（2026-09-24 用户确认）

| 问题 | 决定 |
|---|---|
| 旧程序处理 | 底部小选项，默认「留作备用副本」，可改「删除旧程序」 |
| 只换程序时的程序名 | 改名生效 |
| 新程序来源 | 选文件（与新建程序一致），支持拖入 |
| 范围下拉 | 「通用」、各方案名、分隔线、「+ 新建定制方案…」；新建程序也用它 |

## 3. 对话框

```
正在更新：<程序名> · <程序类型> · <通用|方案名>
新的程序   [拖到这里，或点选择      选择…]
程序类型   [下拉，默认当前类型]
归属厂商   [可编辑下拉，默认当前厂商]
通用/定制  [范围下拉，默认当前范围]
程序名称   [默认旧名；选文件后按文件名预填]
旧程序     (•) 留作备用副本  ( ) 删除旧程序
                              [取消] [更新]
```

- 「更新」在选了文件且名称合法时才可用；不可用原因写在提示行。
- 有借用或默认指向旧程序时，点「更新」后先弹确认列出命中；无命中不打扰。

## 4. 派生规则（`ui_common.workspace_actions.plan_program_update`）

| 类型 | 范围 | 操作 | 新路径 |
|---|---|---|---|
| 同 | 同 | `update_asset` | `旧父目录/<名称>` |
| 变 | 任意 | `change_type` | 按目标范围拼接 |
| 同 | 通用→方案 | `general_to_custom` | `定制/<方案>/<类型>/<名称>` |
| 同 | 方案→通用 | `custom_to_general` | `通用/<类型>/<名称>` |
| 同 | 方案→另一方案 | `custom_scheme_move` | `定制/<方案>/<类型>/<名称>` |

- 类型比较用 `canonical_module_dir`。类型与范围同时变：服务按路径派生为 `change_type`，UI 同样按此派生。
- 名称为空、含 `/` `\`，或 `update` 时与旧名相同（大小写不敏感），返回错误文案，不调用服务。
- 修正旧行为：旧对话框「换到另一模块」一律落到 `通用/`，定制程序改类型会被挪出方案。

## 5. 来源与改名

`update_asset` / `change_asset_semantics` 只收来源目录；`update_asset` 的新目录名取来源目录名。UI 把选中文件复制到系统临时目录下以「程序名称」命名的子目录（`stage_files_as_named_dir`），作为来源传入，调用结束后删除临时目录。不改事务服务。

## 6. 厂商

`change_asset_semantics` 直接带 `vendor`。`update_asset` 不带厂商：成功后厂商与旧值不同时，再对新程序调用 `update_asset_vendor`。

## 7. 验收

- 派生规则每行一个单测；名称错误三种。
- 临时目录：以名称命名、内容为所选文件、调用后可清理。
- 服务：类型与范围同时变的 `change_asset_semantics` 成功落到目标方案（新增服务测试）。
- 对话框：默认值取当前程序；只改文件+名称走 `update_asset` 且来源目录名为新名称；改类型走 `change_type`；范围下拉「+ 新建定制方案…」建完选中、取消回到原选项。
- 新建程序：范围下拉替代单选按钮，提交的 `scope`/`scheme_name` 与下拉一致；借用模式下拉锁定「通用」。

## 8. 人工验证

1. 在 `D:\testprogram` 的 L50S 主板程序上「更新程序」，只选新文件 → 旧程序进备用副本，新程序名按文件名。
2. 同一程序改名称后更新 → 新目录用新名称。
3. 把范围改成某方案 → 程序移到该方案下。
4. 范围下拉里「+ 新建定制方案…」→ 建完自动选中。
5. 新建程序里范围下拉同样可用。

## 9. 备用版本查看与恢复（2026-09-27）

- 工作台“备用版本”入口针对当前选中的本型号程序，列出 `旧版本/` 下的副本、原程序名、退位时间与当前可恢复状态。
- 同类型、同方案且原路径空闲的直接副本可调用 `restore_retired_version`；恢复后当前程序成为新的备用副本。嵌套的更早版本显示在列表中，需先恢复上一层；跨类型、跨方案或元数据无效的副本显示原因且不可直接恢复。
- 借用其他型号的行须到源型号查看；所有恢复仍走工作区写入门闩、确认与事务服务。
- 当前程序未被扫描器识别而不在网格中时，“备用版本”入口可手动选择当前程序目录；恢复服务允许更新流程生成的未识别文件目录，但拒绝仅含元数据和备用副本的空程序。
- [x] 副本列表、不可恢复原因及 Qt 恢复入口的自动化测试通过。
- [x] 用户已确认真实工作区的列表、恢复确认与完成后的程序刷新通过。
