## 二、对四个核心问题的回答

### 问题 1：每个模块保留一个程序做不到

**实际统计**（通用区，已验证的真实文件）：

| 模块 | 变体数 | 文件类型 |
|---|---|---|
| 主板程序 | 2 | `.bin` |
| 手控UI | 2 | `.ROM` + `.PKG` + `.zip` |
| 蓝牙程序 | 3 | `.mot` |
| 语音程序 | 2 | `.bin` + `.zip` + `.xlsx` |
| 快捷键 | 2 | `.hex` |
| 3D机芯版 | 1 | `.mot` |
| 腿部 | 1 | `.hex` |
| **定制手控UI** | **16** | `.ROM` + `.PKG` |

**结论**：多变体合理。用 `模块/变体/` 两级结构。单变体模块（3D机芯、腿部）不需要包子目录。

### 问题 2：定制区留空文件夹

**实际空占位统计**（已修正）：

| 方案 | 空占位 | 真实定制模块 |
|---|---|---|
| 以色列-Royal Z9 | 3 | **主板**、手控UI(3变体)、蓝牙、语音 |
| 葡萄牙-小明 | 2 | **主板**、**快捷键**、手控UI、蓝牙、语音 |
| 西班牙 | 2 | **主板**、手控UI、蓝牙、语音 |
| 越南-娉娉-24模式 | 2 | **主板**、**快捷键**、手控UI、蓝牙、语音(空) |
| 越南-聘聘-12模式 | 4 | 手控UI(2变体)、蓝牙、语音 |
| 马来西亚-ROYAI | 2 | 主板(多版本)、快捷键、手控UI(3变体)、蓝牙、语音、接线图 |

> [!WARNING]
> GPT 方案多处标注的空占位目录不准确。实际上小明有独立快捷键和主板，西班牙有独立主板，越南24模式有独立主板和快捷键。GPT 方案的迁移表需要全面修正。

**解决方案不变**：用 `方案配置.toml` 引用通用模块，替代空占位目录。

### 问题 3：多条件快速搜索

精简方案维持不变。只需新增 4 个字段：

```python
category: Literal["common", "custom", "custom_variant"]
platform: str        # "标准单机芯3D" / "单机芯2D" / "双机芯-上3D-下2D"
scheme_name: str     # 定制方案名
scheme_path: str     # 定制方案根目录
```

GPT 方案的 `region`/`customer`/`language`/`variant` 四个字段不建议入 SQLite，原因：
1. 从目录名自动拆分不可靠（`以色列-家用-蓝牙RoyaI Z9` 怎么拆？）
2. `方案配置.toml` 已存这些字段
3. `scheme_name LIKE '%越南%'` 足以实现地区搜索

### 关键设计变更（vs GPT 方案）

| 点 | GPT 方案 | 本方案 | 理由 |
|---|---|---|---|
| 通用区层级 | `通用/{平台}/{模块}/` 三层 | `通用/{模块}/` 两层 + 双机芯单独子目录 | 2D 无独有程序，不需要单独平台；3D 是默认平台不需要命名 |
| 2D 平台 | 独立平台目录，存独有模块 | **删除**（当前无独有内容） | 已验证 12/12 文件与3D完全相同 |
| 定制区层级 | `定制/{平台}/{方案}/` 三层 | `定制/{方案}/` 两层 | L36 目前只有"标准3D"定制方案，不需要平台中间层 |
| 字段数 | 10 个新字段 | 4 个新字段 | `region`等从 TOML 按需读取 |

> [!TIP]
> **为什么去掉平台中间层？**
>
> 1. 当前 L36 只有 1 个平台有定制方案（标准3D），加平台层级是空架子
> 2. 2D 平台无独有程序，不需要独立目录
> 3. 双机芯只有 1 个独有主板，作为通用区子目录即可
> 4. 如果未来出现 2D 定制方案，再建 `定制/单机芯2D/` 不迟
>
> 当前设计遵循 YAGNI（You Ain't Gonna Need It）——不提前构建不需要的层级。
