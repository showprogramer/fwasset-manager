# REVIEW-20260915-workspace-transaction-foundation：工作区事务基础

结论：通过。公共事务基础可作为后续 CRUD、权威扫描与索引写入的共同依赖；具体业务补偿仍须在各自子任务接入时审查。

## 审查结果

- 状态先于产品写入落盘；首次产品数据变更前 generation 进入奇数，成功、失败和中断收敛为偶数。
- 操作日志在失败与中断时保留。成功路径先落 `clean` 再删除日志；若末步删除失败，事务转为 `recovery_required`，不会丢失恢复线索。
- 状态文件的同目录原子替换、日志删除与无锁读取对 Windows 瞬态共享冲突做有界重试（独立复审实测：句柄被持时替换/删除必然失败，读写两侧原实现都会出错）；瞬时冲突不再误报 `recovery_required`，seqlock 起止偶数判定不变。
- 受管根创建拒绝预先占用或重定向的路径，不覆盖、删除或接管用户内容。认领流程：`exist_ok=False` 建目录 → 复核重定向 → `O_EXCL` 写标记 → 再次复核根身份与标记在位；mkdir 后与标记落盘后的两次复核把「写标记进外部目标」的窗口收敛为可检测、可撤回——发现丢失竞争或替换时只撤回本应用 O_EXCL 新建的标记文件，绝不 rmdir 或触碰外部内容，统一报告 `ManagedRootOccupiedError`（含非竞争写失败：同样只撤回自建标记，留下空的未认领目录交人工处理）。
- 状态/日志写入经模块内所有权校验引导所有权标记（`assert_managed_write` 依赖该标记、无法自举），既有业务写入口的守卫不受影响。
- Windows 命名互斥体按规范化根派生名称，显式配置 Win32 指针签名以避免 64 位句柄截断；同进程重入返回 busy，进程中断由持久化状态/操作日志识别并阻写。
- 无锁预览通过起止一致的偶数 generation 判定可发布；`recovery_required` 的只读警告呈现由后续扫描/UI 接入。

## 验证与剩余风险

- `test_workspace_transaction.py` 覆盖初始化、占用保护、重入锁、seqlock、异常退出、真实子进程写入期退出与恢复、瞬态共享冲突的读/写/删重试与预算有界性、创建期 junction 替换与标记回撤；自动化全量检查与隔离场景脚本 `scripts\verify_workspace_transaction.py`（新增事务、子进程硬退出、恢复收敛与阻写）均通过。
- 极端对抗（替换在复核之后的微秒窗口内来回切换）理论上可能留下一个本应用自建的空标记文件在外部目标，且不删除任何他人内容——这是路径原语无句柄锚定下的固有极限；非竞争初始化失败会留下空的未认领受管目录，下次进入按 occupied 报告并由人工清理。
- 杀毒/备份等外部程序长时间持有状态文件时，写事务仍会在 2 秒重试预算耗尽后失败并进入 `recovery_required`，属既有错误语义；尚无调用方接入，不影响用户可见行为。
- 尚无现有 CRUD 或扫描入口接入本协调器；后续接入必须在锁内重验、在首次磁盘改动前调用 `begin_product_write()`，并为业务日志阶段定义补偿恢复器。
