# Migration: L36 Directory Structure Standardization

Date: 2026-06-06
Scope: `D:\按摩椅相关文件汇总\L36程序`
Status: Completed

## Reason

L36 型号的固件目录从非标准化状态整理为统一的 `通用/定制` 扁平结构，使软件扫描器可以基于 TOML 配置驱动 + 目录扫描辅助的方式工作，而非纯依赖目录名猜测。

## Changes

### 1. 默认变体目录添加 `_默认` 后缀

人为视觉确认 + TOML 权威声明的双轨机制。

| 原路径 | 新路径 |
|--------|--------|
| `通用/主板程序/量产/` | `通用/主板程序/量产_默认/` |
| `通用/手控UI/量产中性/` | `通用/手控UI/量产中性_默认/` |
| `通用/蓝牙程序/中文-通用/` | `通用/蓝牙程序/中文-通用_默认/` |
| `通用/快捷键/量产/` | `通用/快捷键/量产_默认/` |
| `通用/语音程序/中文-通用/` | `通用/语音程序/中文-通用_默认/` |

### 2. 单模块变体命名统一

`定制/单模块变体/` 内子目录重命名以与通用区一致：

| 原名 | 新名 |
|------|------|
| `主板/` | `主板程序/` |
| `语音/` | `语音程序/` |

### 3. 单模块变体归入通用区

所有单模块变体从 `定制/单模块变体/` 迁移到 `通用/` 对应模块目录下，然后删除 `定制/单模块变体/` 整个目录。

迁移动作：
- `定制/单模块变体/主板程序/` 下 4 个子目录 → `通用/主板程序/`
- `定制/单模块变体/手控UI/` 下 15 个子目录 → `通用/手控UI/`
- `定制/单模块变体/语音程序/` 下 2 个子目录 → `通用/语音程序/`

设计原则：定制区仅保留整机方案，单模块变体归入通用区，搜索按关键字即可命中（如 "L36 主板 防夹功能"）。

### 4. 删除定制方案空占位目录

定制方案中缺失的模块不再保留空目录，回源逻辑由 `平台配置.toml` 和软件处理。

| 已删除路径 |
|-----------|
| `定制/越南-娉娉-12模式/主板程序/` |
| `定制/越南-娉娉-12模式/快捷键/` |
| `定制/越南-娉娉-24模式/语音程序/` |
| `定制/以色列-Royal-Z9/快捷键/` |
| `定制/西班牙/快捷键/` |

### 5. 新增配置文件

**`L36程序/平台配置.toml`** — 声明每个平台下各模块的默认变体，作为软件回源的权威来源。

```toml
[[platform]]
name = "标准单机芯3D"
[platform.defaults]
主板程序 = "量产_默认"
手控UI = "量产中性_默认"
蓝牙程序 = "中文-通用_默认"
快捷键 = "量产_默认"
语音程序 = "中文-通用_默认"

[[platform]]
name = "双机芯-上3D下2D"
[platform.defaults]
主板程序 = "量产_默认"
手控UI = "手控UI-同L50S"
快捷键 = "L36 快捷键 (通用)"
...
```

### 6. 数据模型变更预告

`FirmwareAsset` 的 `category` 字段从 `Literal["common", "custom", "custom_variant"]` 简化为 `Literal["common", "custom"]`。原因：单模块变体已归入通用区，不再需要 `custom_variant` 类别。

## Agent Impact

- 扫描器代码需新增读取 `方案配置.toml` 和 `平台配置.toml` 的逻辑，先读 TOML 再遍历目录。
- `定制/` 下的每个子目录都含有 `方案配置.toml`，scanner 应以此作为识别定制方案的入口，而非硬编码目录结构。
- 默认变体目录带 `_默认` 后缀，scanner 在匹配 `dir_keywords` 时需注意后缀不影响关键字匹配。
- `双机芯-上3D-下2D/` 下的跨型号引用（`.ref` 文件和 `-同L50S` 后缀目录）为临时方案，L50 整理完成后需统一处理。
- 空占位目录已删除，定制方案缺失模块时不应在目录中看到空文件夹，回源逻辑由软件根据 `平台配置.toml` 处理。
