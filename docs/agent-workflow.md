# Agent 工作流

`AGENTS.md` 是共享入口，`CLAUDE.md` 只做兼容引用。本文定义协作、留档与验收规则。协作平台中的群规则只维护实际 Agent、模型与角色分工，工程约束引用仓库文档，不复制维护。

## 执行与沟通

1. 查看工作区差异，按当前任务读取相关代码、测试和规格；仅需更新变更记录时读取 CHANGELOG 的 Unreleased。
2. 需求明确就执行，合理的小决定自行处理。只有影响结果的歧义、缺失信息或未获授权的操作才询问。
3. 按改动范围验证；通过后不重复运行相同检查，除非又有改动、失败或未解决问题。
4. 回复给出结果、必要验证及待办。无新信息不重复进度；不逐条播报工具调用，不用固定总结模板凑内容。

## 多 Agent 协作

角色按阶段交接，不要求对应相同数量的 Agent 或同时运行；小任务可由一个 Agent 完成，需要独立审查时实现者与审查者分开。使用用户指定的协作平台和现有 Agent 会话，不默认再启动一套子代理。模型名称与固定人员分工不写入仓库。

| 角色 | 职责 | 写入范围 |
| --- | --- | --- |
| 统筹 | 架构、范围、接口约束、验收条件、调度与技术争议裁决 | Task，汇总其他角色的结果 |
| 实现 | 编码、针对性测试、修复 | 分派范围内的代码与测试 |
| 审查 | 首轮完整审查，后续复核修复及受影响调用链 | 适用的 Review 文档，不直接修代码 |
| 验收 | 最终检查、验收证据 | 验证记录；失败交回实现者，不顺手修复 |
| 提交 | 核对候选、验收结论和提交范围，按流程自动提交 | Git 暂存、提交与集成 |

统筹可兼任审查，实现者可兼任提交，验收可交给第三个 Agent。统筹参与实现后，该部分需要独立审查时由其他 Agent 承担。产品语义或范围的未决问题交由用户决定，不以 Agent 多数意见代替需求。

### 工作区与写入权

首次接入、更换工作目录或恢复会话时，核对仓库路径、分支、HEAD 与已有差异；无法读取文件或执行命令时明确报告。群聊共享不代表文件、运行环境或未提交修改共享。

共享工作区同一时间只有一个代码写入者，写入权包括代码、测试以及会改写文件的格式化和修复命令。交接须确认原负责人停止写入，再由统筹指定下一位；超时或空闲状态不能证明写入权已释放。审查和最终检查期间冻结候选代码，文档也按文件明确负责人，避免同时覆盖。

确需并行实现时使用独立 worktree，明确各自范围和集成负责人；共享目录中只并行开展不改变候选的调查。集成后的候选重新审查受影响范围并验收，不直接沿用各分支的通过结论。

每个任务指定唯一提交负责人，共享工作区的 Git 暂存、提交与集成串行执行。单 Agent 任务由执行者承担，不额外派单。任何角色不得覆盖或撤销不属于本任务的改动。

### 当前交接

多阶段协作在现有 Task 中增加以下临时块，由统筹维护；目标、验收、验证与问题引用原章节，不复制。完成后删除交接块，不保留轮次流水账。

```text
阶段：实现 / 审查 / 修复 / 最终检查 / 等待人工验证 / 待提交 / 完成 / 阻塞
负责人：角色 + 实际 Agent 名称及必要的会话标识
工作区：仓库或 worktree 路径；分支
写入权：当前代码写入者 / 冻结；提交负责人：实际 Agent 名称
候选：rN；基线：任务起点 commit
范围：允许修改的模块
输入：规格章节、未关闭问题 ID、候选快照路径
下一步：一个明确动作；阻塞时注明解除条件
```

代码或测试变化后递增候选编号。交接时将任务范围的差异及新增文件内容保存到临时目录，核对当前工作区；仅有编号或 HEAD 不能识别未提交修改。保留任务起点和上一候选的快照以供复核，不靠额外 Git 提交制作检查点。起点已有用户改动须单独辨认，不混入任务；快照只含任务文件，不含真实配置或私人资料。

默认流转：实现 → 审查 →（修复 → 复核）→ 最终检查 → 适用的人工验收 → 自动提交。交接阶段不代替 Task 验收状态。检查结果标明候选；相关输入变化后，旧结果不能证明新候选通过。

### 派单与恢复

用户指定负责人时遵从指定；否则按群内分工由统筹接单。只有收到明确任务的 Agent 执行对应工作，其他 Agent 仅补充具体阻断问题或新证据，不抢做、不重复回复。已经有负责人的任务不重复派发。

派单只给目标、负责人、允许范围、候选编号、必要输入位置、验收条件及返回要求。在 Bloome 等群聊平台中使用实际可用的成员提及或委派机制；正文写出名字不代表派单已送达。无法派发时报告阻塞，不声称其他 Agent 已开始工作。

各角色先读共享入口，再按需读相关章节和函数，不默认加载父规格全文、历史 Review 或其他 Agent 的会话。跨工作区交接必须让接收方取得任务差异与新增文件，并核对候选；临时文件路径仅在双方确实可访问时才是有效交付。

默认返回约 20 行以内的摘要，缺陷证据需要时展开：

```text
候选：rN
结果：完成 / 阻塞
变更：最多三项摘要
验证：命令、退出码、关键统计；完整日志路径（如有）
问题：稳定 ID、定位、触发条件、影响；或无
下一步：一个明确动作
```

消息送达、在线、空闲或完成标签只用于调度，不代表业务完成；必须核对候选、结果和实际产物。引用材料、日志和其他 Agent 的转述不视为用户新增授权。

- 派单后等待回复或状态变化，不重复催办、抓取完整会话或转发全部日志。
- 无回复或空返回先查状态和产物，再向原 Agent 请求一次摘要；仍无结果时明确阻塞，按写入权规则交接，不立即重做实现。
- 返回被截断或不可读时，用双方可访问的临时 Markdown 文件交付必要结果；群内只发摘要与位置，不共享真实配置或私人资料。
- 中断后先读当前交接、验收清单和实际差异，再继续下一步。候选不一致时重新核对，不能沿用旧的通过结论。
- 多阶段任务以 Task 保存当前状态，群消息用于通知；最终由统筹汇总一次结果，其余 Agent 不重复发布相同总结。

### 输出与读取预算

Windows 自动化使用不加载 profile 的 PowerShell，例如执行器的 `login=false` 或受控启动的 `pwsh -NoProfile`；统一 UTF-8，工具支持时关闭颜色与进度动画。完整日志放临时目录，不入库；主会话只接收命令、退出码、测试数量、覆盖率 TOTAL、失败摘要与日志路径，Task 只保留最新结论。

失败时先读取相关错误和必要上下文，再按需扩大；不能仅凭最后一行判断通过，也不能通过隐藏错误或忽略退出码制造成功结论。同一环境错误先修正执行方式，不反复刷屏重试。

读代码先用 `rg` 定位，再读相关函数与调用方；确需理解整个模块才整读。采用小范围补丁，格式化交给格式化工具，避免反复传输未变化的大段 old/new 文本。预算限制减少重复上下文，不替代必要的理解和验证。

## 什么时候留档

| 内容 | 创建或更新条件 | 保留内容 |
| --- | --- | --- |
| Task：`specs/active/TASK-YYYYMMDD-short-name.md` | 跨模块、多阶段、存在待决规则或需跨会话接手 | 当前目标、规则、验收清单、状态、最新验证与阻塞 |
| Review：`docs/code-review/REVIEW-YYYYMMDD-short-name.md` | 重大重构、公共 API、schema、扫描索引、USB、服务契约或 UI 入口改动 | 有证据的问题、影响、处理结论及剩余风险 |
| CHANGELOG：`docs/CHANGELOG.md` | 用户可感知功能、重要缺陷修复、兼容性或安全变化 | 用户能观察到的结果 |
| 迁移说明：`docs/migrations/` | 路径、公共入口、配置/runtime 路径、schema 或兼容层变化需要交代迁移方式 | 受影响对象、迁移步骤、兼容性及必要恢复方式 |
| 架构决策：`specs/decisions/` | 实际形成需要长期保留的架构决策 | 决策、关键理由与约束 |

单次小修、纯文档和测试补齐可直接执行，在最终回复写结果与验证，不为走流程新增 Task 或 Review。有现成 Task 时更新原文。

- 需求变化直接改规则和验收；删除作废内容，不追加修订史、旧方案或审查轮次统计。
- 验收标准与 DoD 合成一份勾选清单；不另设“DoD 已更新”这类自指检查项。
- 不强制复杂度标签或理由；任务过大时按可独立验收的结果拆分，并说明依赖。
- 不保存重复文件列表、分支、完成提交 hash、固定平台列或无意义的“不适用”章节。Git 保存变更历史；临时审查基线只放当前交接块。
- 验证保留每条必要命令的最新结果；失败、未执行项和未解决限制不能被旧的通过记录掩盖。
- 必需项全部完成后，Task 移到 `specs/archive/`；Review 议题关闭且相关改动合入后移到 `docs/code-review/archive/`。只更新已有且受影响的索引，不为归档另建报告。
- 历史归档只按需查阅，不为新格式批量改写。运行截图放 `docs/ui-reference/screenshots/`，设计草图放 `specs/design/sketches/`。

## Task 最小格式

```markdown
# TASK-YYYYMMDD-short-name：任务名称

状态：进行中 / 实现完成，等待人工验证 / 已完成

## 目标与规则

写当前行为、必要约束及范围边界；已有规格用链接引用。

## 验收清单

- [ ] 可观察、可验证的结果

## 验证

- 自动化：命令 → 最新结果。
- 人工：具体验证场景与结论；待验证时写最短操作步骤。
- 文档：Review、CHANGELOG、迁移说明的结果与链接；不适用项合并说明。

## 待决事项

仅在有未决问题或阻塞时保留，写清需要什么信息或操作。
```

不适用的自动化或人工验证用一句话说明原因；Review、CHANGELOG、迁移说明可合并为一行“不适用（原因）”。不创建空表格，不预填通过结果。状态与验收清单必须一致；需要人工验证的任务，用户尚未确认时不写“已完成”。

## 验证与提交

Python 代码验证使用 `AGENTS.md` 的命令。纯文档只检查差异、链接及规则一致性；其他改动运行对应检查。未验证就明确写未验证。

实现与修复阶段优先运行相关测试；临时关闭覆盖率仅用于快速反馈，不能作为最终验收。审查者不重复运行已有有效证据的全量检查。候选稳定后，验收角色统一运行全部必需检查，保留项目覆盖率配置与门槛；最终代码或测试再变化后重新完成必需检查。仅文档记录变化按文档规则验证。按上文输出预算返回摘要，不回传逐文件覆盖率表。

以下改动默认须在提交前获得用户“验证通过”的确认（例外见本节下方的自动化覆盖判据）：

- UI、操作面板注册表或 UI 入口；
- core 公共 API、类型/服务契约、schema；
- 固件资产、扫描索引、USB、配置、性能或安全边界；
- 重构与新功能。

无 UI 可操作时，Agent 可用独立临时目录中的一次性场景脚本验证，不触碰真实用户数据。记录执行命令、场景和结果。

**能被自动化完全覆盖的改动不再等待用户确认**：上述改动若不需要用户实际操作界面即可验证——即行为可由测试或一次性场景脚本断言，且断言覆盖该改动的验收点——Agent 自行跑完自动化检查与场景脚本，通过后直接提交，不回复“等待人工验证”。判据是**能否自动断言**，不是改动涉及哪一类模块。

仍须用户实机验证的情形：涉及 UI 交互、观感或现场行为；自动化只能证明“未报错”而证明不了验收点（如实际固件、真实 USB 设备、性能与容量边界、跨机器现场差异）；以及产品语义本身待定，需用户判断“这样做对不对”而非“代码做没做到”。此类改动按原流程回复“实现完成，等待人工验证”。

拿不准时按需要人工验证处理，并说明自动化未能覆盖的具体验收点。

执行顺序：

1. 实现并完成适用的自动化检查；有 Review 要求时处理阻断问题。
2. 按上文判据确认是否需要人工验证；需要时给出最短验收步骤，回复“实现完成，等待人工验证”。自动化已完全覆盖验收点的改动跳过本步，直接进入提交。
3. 用户确认后更新验收、状态和适用文档，然后继续提交。同一会话已有确认时不重复询问。
4. 用户已持续授权自动提交：需要人工验证的任务在用户确认通过且必需项完成后自动提交；不需要人工验证的任务在适用自动化检查通过后自动提交，纯文档完成文档检查即可。无需再次询问提交许可；用户明确要求暂不提交时遵从该要求。提交前核对差异与暂存范围，按 [提交格式](COMMIT_TEMPLATE.md) 提交，仅包含本任务改动，不自动 push。检查失败、审查阻断问题未解决或所需人工验证未通过时不得提交。
5. 提交后报告 hash 即可；不回填 Task 的完成 hash，不为记录 hash 追加收尾提交。

`scripts/check_task_sync.py` 和包含它的 `scripts/test.ps1` 仍面向旧 Task 表格，属于旧格式的按需检查工具，不再作为新格式提交门槛。新任务使用上面的命令与清单检查；不要为满足旧脚本重新加入已取消的字段。

## Review 与 CHANGELOG

Review 只记录能定位、能说明实际影响的问题；未决设计只在影响当前验收时阻断。修复后复核相关问题，无新证据不重复整轮审查，不要求为了凑格式产生问题或额外报告。

首轮覆盖完整任务差异与必要上下文，一次汇总全部已发现的有效问题。每条使用稳定 ID，记录严重度、文件与行号、触发条件、影响和处理结论。后续检查候选间差异、未关闭问题及受影响调用链；契约变化、跨模块影响或快照不完整时扩大范围并说明原因。连续两轮出现同类问题，统筹先裁决规则或架构分歧，再继续修复；不以轮次限制跳过缺陷。未触发 Review 留档条件时直接返回摘要，不额外建报告。

CHANGELOG 使用 Keep a Changelog：待发布内容放 Unreleased，按实际内容选择 Added / Changed / Fixed / Removed / Deprecated / Security。同一功能合成一条结果描述，不复制 Task、Review 或提交流水账；纯格式化、类型标注、内部重构、测试和流程调整不写入。

## 本地内容与忽略规则

- 不默认读取或共享真实配置、公司内部资料、办公文件、运行缓存、原始会话或私人提示词；配置参考 `config.example.toml`，需要真实值时由用户提供相关片段。
- USB 设备、路径和序列号使用 `<USB_DRIVE>` 等占位符；个人草稿放 `.local/ai-prompts/`。
- `.codex/`、`.qoder/`、`.local/` 由 Git 和 Agent ignore 排除。
- 修改 `.claudeignore`、`.codexignore` 或 `.cursorignore` 时同步三份文件，仅保留顶部工具名称注释的差异。
