# Agent 工作流

`AGENTS.md` 是共享入口，`CLAUDE.md` 只做兼容引用。本文只补充协作、留档与验收规则，按当前阶段读取。

## 多 Agent 协作

默认由接收需求的 Agent 完成实现、文档、验证和提交，兼任协调者。需要协作时，根据当前环境选择可用的 Agent 委派、消息和等待机制；不绑定特定宿主，也不设只转发消息的常驻主控。

### 何时增加 Agent

| 任务 | 默认安排 |
| --- | --- |
| 小修、纯文档、测试补齐 | 一名 Agent 完成，不为角色齐全另开会话 |
| 触发下文 Review 留档条件，或涉及安全、数据丢失风险 | 一名实现者加一名独立审查者；候选稳定后交审 |
| 其他改动 | 实现者完成；存在具体疑点或用户要求时增加独立审查 |
| 有明确独立产物的调查或跨模块实现 | 才考虑第三名，派单前说明独立范围与收益；并行写入遵守下文 worktree 规则 |

文档默认随实现更新，只有文档本身构成独立交付时才单独派单。实现者负责修复审查问题，审查者不接管实现；用户负责待定产品语义及必须人工验证的场景。任务之间按需启用角色，不保持所有 Agent 持续工作。

### 派单与写入权

- 一次派发一个可验收阶段，只给目标、负责人、修改范围、必要输入和验收条件。执行者自行完成实现、针对性测试和常规修复，遇到影响范围、契约或授权的阻塞再返回。
- 输入优先引用当前规格、相关代码路径和候选差异，不转发完整对话，不要求各 Agent 重做全仓库调查。协调者核对验收证据和关键差异，不重复执行已委派的完整任务。
- 接手时核对路径、分支、HEAD 和已有差异。共享工作区同时只有一个代码写入者，包括测试、格式化和自动修复；文档按文件分配。原负责人明确停止写入后才能交接，审查及最终检查期间冻结候选。
- 并行实现须使用独立 worktree，指定集成负责人；集成后重新审查受影响范围并验收。共享目录只并行开展只读调查。
- 每个任务只有一个提交负责人，负责暂存、提交与集成；单 Agent 任务由执行者承担。保留其他任务和用户的改动。
- 审查者只报问题，修复交回实现者。需要独立审查时不得自审；产品语义由用户决定。

### 等待与返回

- 派单时使用当前环境可用的 Agent 委派功能，明确目标、负责范围和验收条件；等待使用对应的等待机制。有独立工作就继续，否则等待，不循环查询状态、读取其他 Agent 会话或催办。
- 优先保持同一个异步等待调用；宿主要求有界等待时，超时后续等，不附带日志读取。超时不代表失败或写入权释放，不重复派单。
- 完成后读取一次摘要并核对产物；状态标签不是验收证据。异常时才查状态及必要输出，审批界面不自动代答。结束却无结果时向原 Agent 请求一次摘要，仍无结果则报告阻塞。
- 输出截断时有限扩大一次读取范围；仍不完整则请原 Agent 写入双方可访问的临时 Markdown 文件，只返回路径。
- 宿主无法继续等待时保存当前交接，说明如何恢复，不声称后台仍在自动统筹。

返回控制在约 20 行：候选、完成或阻塞、变更摘要、验证结果、未解决问题、是否停止写入、下一步。不转发完整日志或其他 Agent 会话；只由统筹向用户汇总最终结果。

### 当前交接

需要跨 Agent 或跨会话接手的多阶段任务在现有 Task 中保留一个当前交接块，由统筹维护；完成后删除，不另建心跳、日报或会话档案。用户根据额度和工作安排决定何时转交；收到用户的 `handoff` 请求后，执行者在操作系统临时目录写交接文档并把路径交给用户，由用户转给 Grok、Claude Code 或其他接手 Agent，不自动派单。文档概述目标、现状、工作区路径、最新验证和待办，列出建议技能；已有规格、计划和差异只引用，不重复复制。小任务的一次性审查直接在派单中提供候选和验收信息，不为交接另建 Task。

```text
阶段：实现 / 审查 / 修复 / 最终检查 / 等待人工验证 / 待提交 / 阻塞
负责人：实际 Agent 名称；代码写入者或冻结；提交负责人
工作区：路径、分支；基线：任务起点 commit；候选：rN
范围与输入：规格章节、任务差异快照、未关闭问题
下一步：明确动作；阻塞时注明解除条件
```

交接候选涉及的代码或测试变化后递增候选编号。已提交且工作区干净的候选使用基线和候选 commit 标识；未提交候选保存任务起点、上一候选（如有）及当前候选的任务差异和新增文件到临时目录，区分起点已有改动，仅有 HEAD 或编号不足以识别未提交内容。跨工作区先确认接收方能取得这些产物，不包含真实配置或私人资料。

接手或恢复只读共享入口、当前交接、验收清单及相关差异，按需展开代码。验证结论绑定候选，相关输入变化后重新验证，不能沿用旧结论。

## 输出与读取预算

使用不加载 profile 的 PowerShell（如 `login=false`），统一 UTF-8。先用 `rg` 定位，再读相关函数和调用方；不默认整读规格、模块或历史 Review。

完整日志放临时目录，主会话只接收命令、退出码、关键统计、失败摘要及日志路径。失败时按需展开，不能隐藏错误或只凭最后一行判断通过。同一环境错误先修正执行方式；没有输入变化或新问题，不重复检查。

## 什么时候留档

| 内容 | 触发条件 | 保留内容 |
| --- | --- | --- |
| Task：`specs/active/` | 跨模块、多阶段、需跨会话接手或有待决规则 | 目标、规则、验收、最新验证及阻塞 |
| Review：`docs/code-review/` | 重大重构、公共 API、schema、扫描索引、USB、服务契约或 UI 入口改动 | 有证据的问题、处理结论及剩余风险 |
| CHANGELOG：`docs/CHANGELOG.md` | 用户可感知功能、重要修复、兼容性或安全变化 | 用户能观察到的结果 |
| 迁移说明：`docs/migrations/` | 路径、公共入口、配置/runtime、schema 或兼容层变化需要迁移 | 影响、迁移步骤及必要恢复方式 |
| 架构决策：`specs/decisions/` | 形成长期有效的架构决策 | 决策、理由与约束 |

小修、纯文档和测试补齐不另建 Task 或 Review。已有文档直接更新，不记录流水账、作废方案、重复文件列表、完成 hash 或空章节；验收与 DoD 共用一份清单。验证只保留最新结果，不能用旧的通过记录掩盖失败或未执行项。

必需项完成后 Task 移到 `specs/archive/`；Review 问题关闭且改动合入后移到 `docs/code-review/archive/`。仅更新受影响的已有索引，不批量改写历史。运行截图放 `docs/ui-reference/screenshots/`，设计草图放 `specs/design/sketches/`。

## Task 最小格式

```markdown
# TASK-YYYYMMDD-short-name：任务名称

状态：进行中 / 实现完成，等待人工验证 / 已完成

## 目标与规则

当前行为、约束及范围；已有规格用链接引用。

## 验收清单

- [ ] 可观察、可验证的结果

## 验证

必要命令、场景及最新结果；待人工验证时写最短操作步骤。
适用的 Review、CHANGELOG 或迁移说明用链接引用。
```

有阻塞才增加“待决事项”。不适用的验证简述原因，不预填通过；状态须与验收清单一致。

## 验证与提交

1. 实现阶段先跑相关测试；候选稳定且审查阻断问题解决后，由验收负责人统一运行 `AGENTS.md` 的必需检查，保留覆盖率门槛。审查者不重复已有有效全量验证；最终代码或测试再变化后重跑必需检查。纯文档检查差异、链接及规则一致性。
2. UI、核心公共 API、类型/服务契约、schema、扫描索引、USB、配置、性能或安全边界、重构和新功能默认需要人工验证；但验收点可由测试或独立临时目录中的场景脚本完全断言时，自动化通过即可提交，不等待用户确认，也不触碰真实用户数据。
3. UI 交互或观感、真实设备或现场差异、无法自动断言的性能容量边界，以及待定产品语义仍需用户确认。明确未覆盖的验收点和最短步骤，回复“实现完成，等待人工验证”；不确定能否覆盖时也按此处理。
4. 必需检查及适用人工验证通过后，更新验收与文档，按 [提交格式](COMMIT_TEMPLATE.md) 自动提交，无需再次询问许可；用户要求暂不提交时遵从。核对候选及暂存范围，只提交本任务内容，不自动 push。
5. 报告提交 hash，不为回填 hash 或重复状态追加提交。检查失败、审查阻断或所需人工验证未通过时不得提交。

`scripts/check_task_sync.py` 及包含它的 `scripts/test.ps1` 面向旧 Task 表格，不是新格式提交门槛；不要为旧脚本恢复已取消字段。

## Review 与 CHANGELOG

首轮审查完整任务差异及必要上下文，一次汇总有效问题；每条使用稳定 ID，记录严重度、定位、触发条件、影响和处理结论。后续只复核候选间差异、未关闭问题及受影响调用链；契约变化、跨模块影响或快照不全时扩大范围并说明原因。

连续两轮出现同类问题，统筹先裁决规则或架构分歧；不以轮次限制跳过缺陷，不为凑格式制造问题。未触发留档条件时直接返回摘要。

CHANGELOG 的 Unreleased 按 Added / Changed / Fixed / Removed / Deprecated / Security 分类，同一功能合成一条结果；纯格式化、类型标注、内部重构、测试和流程调整不记录。

## 本地内容与忽略规则

- 不默认读取或共享真实配置、内部资料、运行缓存、原始会话或私人提示词；配置参考 `config.example.toml`。
- USB 路径和序列号使用占位符；个人草稿放 `.local/ai-prompts/`。`.codex/`、`.qoder/`、`.local/` 由 Git 和 Agent ignore 排除。
- 修改 `.claudeignore`、`.codexignore` 或 `.cursorignore` 时同步三份，仅保留顶部工具名称注释的差异。
