# /codex-review

参数（可选）：规格路径、重点关注点、对比基线（默认 `HEAD`）。

1. 确认差异就是本任务范围（`git status --short`）；混有无关改动时先告诉用户。
2. 运行（耗时几分钟，timeout 设 600000）：

   ```bash
   uv run python scripts/cross_review.py --spec <规格路径> --focus "<重点>"
   ```

   没有的参数省略。失败时把 stderr 摘要告诉用户，不自行改用同模型审查。
3. 逐条核实 Codex 的问题：读对应代码，能复现或能说明触发路径才算成立。不盲信，也不因为是外部意见就全部驳回。
4. 向用户简报：成立 / 不成立（附一句理由）/ 需要用户裁决的产品语义。然后修复成立的问题，跑 `AGENTS.md` 的必需检查。
5. 修复涉及范围较大时，可以再跑一轮，用 `--focus` 只看修复点；同类问题连续两轮出现就停下来请用户裁决。
